# Изменения, которые были внесены

В ходе подготовки проекта к многопоточному запуску были выполнены следующие изменения:

- Разделены `UserSessionExtension` для API- и UI-тестов.
- `SessionStorage` переработан для работы в нескольких потоках с использованием `ThreadLocal`.
- Добавлена очистка данных `ThreadLocal` после завершения каждого теста.
- После выполнения каждого UI-теста реализовано закрытие браузера (`Selenide.closeWebDriver()`).
- Убрано постоянное логирование HTTP-запросов и ответов `RestAssured`.
- Настроено логирование `RestAssured` только при падении тестов.

# Анализ многопоточного выполнения

Во время выполнения тестового набора использовались рабочие потоки `ForkJoinPool`.

Наибольшую нагрузку получили:

- `ForkJoinPool-2-worker-2` — 6575 мс;
- `ForkJoinPool-2-worker-7` — 6484 мс;
- `ForkJoinPool-2-worker-3` — 6318 мс.

Среднюю нагрузку получили:

- `ForkJoinPool-2-worker-6` — 4215 мс;
- `ForkJoinPool-2-worker-5` — 3611 мс;
- `ForkJoinPool-2-worker-8` — 3405 мс;
- `ForkJoinPool-2-worker-12` — 3094 мс;
- `ForkJoinPool-2-worker-9` — 2781 мс.

Оставшиеся воркеры завершили работу быстрее, так как выполняли меньше тестов либо тесты с меньшим временем выполнения.

Наиболее длительными отдельными тестами стали:

- `userCannotTransferWithInvalidDataTest()` — 3611 мс;
- `userCanTransferWithValidDataTest()` — 2781 мс;
- `userCanDepositWithValidData()` — 2095 мс;
- `userCannotTransferWithoutConfirmTest()` — 1860 мс;
- `userCannotUpdateNameWithInvalidDataTest()` — 1629 мс.

По результатам запуска видно, что нагрузка распределяется между потоками неравномерно. Это связано с тем, что разные
тесты имеют различную продолжительность выполнения. Более длительные тесты занимают поток дольше, поэтому
суммарное время работы отдельных воркеров отличается.

# Вывод

После внесенных изменений удалось сократить общее время выполнения тестового набора с **37,23 с** до **20,72 с**.

При последовательном запуске непосредственно выполнение тестов занимало **35,42 с**, а подготовка Maven — **1,81 с**.

После перехода на многопоточное выполнение время выполнения тестов сократилось до **19,30 с**, а время подготовки Maven
составило **1,42 с**.

В результате:

- общее время выполнения уменьшилось примерно на **44 %**;
- тесты стали выполняться примерно в **1,8 раза быстрее**.

Во время первых попыток запуска в несколько потоков общее время выполнения увеличилось почти до **76 секунд**.
Анализ показал, что причиной было отсутствие закрытия браузеров после выполнения UI-тестов. Из-за этого новые тесты ожидали
освобождения браузерных сессий Selenoid.

После добавления закрытия браузера (`Selenide.closeWebDriver()`) и отключения постоянного логирования `RestAssured` удалось
устранить эту проблему и получить стабильное ускорение многопоточного запуска.
